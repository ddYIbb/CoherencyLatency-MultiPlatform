CoherencyLatency Android 使用手册

版本： 1.2.0（对应 MicroBenchX 1.0.5） 适用平台： Android 4.1（API 16）及以上，arm64-v8a / armeabi-v7a / x86 / x86_64 四种 ABI。 运行方式： 命令行程序（Termux 或 adb shell），没有图形界面，也不是 APK。

重要限制：Android 的 sched_setaffinity 只是“请求”。big.LITTLE 调度器、cgroup 和厂商内核都可能覆盖掩码。 程序会校验绑定结果：每个线程在开始前用 sched_getaffinity 确认掩码、用 sched_getcpu() 确认自己真的落在目标 CPU 上， 每轮测量前后再复核一次。任何一个线程没绑住，这个核心对（含转置格）就写 N/A，不会拿错核上的数字冒充结果。 即使校验通过，矩阵里的 i/j 也只是逻辑槽位，不等于物理核心编号。

1. 文件说明

CoherencyLatency-Android-v1.2.0/
├── CoherencyLatency-arm64-v8a      主流手机（64 位 ARM），推荐
├── CoherencyLatency-armeabi-v7a    老设备（32 位 ARM），Android 4.1+
├── CoherencyLatency-x86            32 位 x86 模拟器 / Atom 平板
├── CoherencyLatency-x86_64         64 位 x86 模拟器 / Chromebook
├── SHA256SUMS
├── README.md
└── LICENSE

四个文件都是独立可执行程序，只依赖 Android 自带的 libc.so、libm.so、libdl.so， C++ 运行库已静态链接进去，不需要 root，不需要安装任何依赖。

2. 怎么选版本

在手机上装个终端（Termux），或连上电脑用 adb，先看 ABI：

getprop ro.product.cpu.abi
输出用哪个文件
arm64-v8aCoherencyLatency-arm64-v8a
armeabi-v7a / armeabiCoherencyLatency-armeabi-v7a
x86_64CoherencyLatency-x86_64
x86CoherencyLatency-x86

绝大多数 2016 年以后的手机都是 arm64-v8a。

系统版本下限由 ABI 决定：32 位 ARM/x86 库按 API 16（Android 4.1） 编译， 64 位 ARM/x86_64 库按 API 21（Android 5.0） 编译——bionic 的 64 位 ABI 从 21 才开始有。 也就是说 Android 4.1~4.4 的老机器只能用 32 位那两个文件。

3. 用 Termux 运行（日常使用）

3.1 安装 Termux

从 F-Droid 或 GitHub 安装 Termux（Google Play 上的版本已停止更新，不建议）。 不需要 pkg install 任何东西，程序自带全部依赖。

3.2 放文件并执行

把对应文件传到手机上（数据线、网盘、scp 都行），然后在 Termux 里：

mkdir -p ~/bin
mv CoherencyLatency-arm64-v8a ~/bin/cl
chmod +x ~/bin/cl
~/bin/cl --list

看到 CPU 信息和 Runtime: Android ARM64 (aarch64), native 就说明能跑。

3.3 快速测试

~/bin/cl --yes --cpus 2 --iterations 100000 --runs 2

只测 2 个逻辑槽位，手机上一两秒就能出结果，适合先确认可用。

3.4 完整矩阵

~/bin/cl --yes --cpus 4 --iterations 200000 --runs 3

槽位数越多，耗时按 n × (n−1) 增长：4 槽 12 对、8 槽 56 对。8 核手机跑满全矩阵要几分钟， 而且会明显发热降频，建议先小规模试。

4. 用 adb 运行（调试用）

adb push CoherencyLatency-arm64-v8a /data/local/tmp/cl
adb shell chmod 755 /data/local/tmp/cl
adb shell "cd /data/local/tmp && ./cl --list"
adb shell "cd /data/local/tmp && ./cl -y --cpus 2 -i 100000 -r 2"
  • /data/local/tmp 是 adb 默认可写目录，普通应用看不见这里，适合临时压测。
  • 一定要先 cd：adb shell 的初始目录是 /（只读），CSV 写不进去。

5.3 绑核失败时显示 N/A

如果某个逻辑槽位绑不上（例如该 CPU 被下线、被 cgroup 排除，或厂商内核拒绝了掩码）， 这一对不会输出数字，而是写 N/A；其余核心对照常测量，程序正常结束（退出码 0）。

下面是在模拟器上把 CPU3 下线后运行 --cpus 4 的真实输出：

Latency matrix (ns per operation; diagonal x):
x,24.990000,24.657501,N/A
24.990000,x,37.193748,N/A
24.657501,37.193748,x,N/A
N/A,N/A,N/A,x
Warning: 6 core pair(s) could not be pinned to the requested processors; those cells are N/A.

CSV 里同样是 N/A：

;Core 0;Core 1;Core 2;Core 3
Core 0;x;24.99;24.6575;N/A
Core 1;24.99;x;37.1937;N/A
Core 2;24.6575;37.1937;x;N/A
Core 3;N/A;N/A;N/A;x
  • N/A 不是 0，也不是“延迟很低”，它表示这一对没有测到可信数据，做统计时要剔除。
  • 每轮等待的首轮上限是 20 秒，之后按上一轮实测时间放宽（至少 5 秒），不会像旧版那样固定 500 ms

就把整张矩阵判死；某一轮真的卡住时只把这一对记为 N/A，并自动重试一次，其余核心对照常跑完。

  • 只是“结果里出现 N/A”不会让程序失败；只有用户按 Ctrl+C 或参数错误才会返回非 0。
  • 想避免 N/A，可以放开对 CPU 的限制（恢复被下线的核、调整 cgroup/cpuset），

或缩小槽位数量，例如 --cpus 3 只用前三个槽位。

  • 用 --no-affinity 时不做绑定、也就不会出现 N/A，但这时测的是调度器自由摆放的结果。

5.4 CSV 写不进去怎么办

当前目录只读时（例如 adb shell 的 /），程序不会丢掉测量结果，而是自动改写到 $TMPDIR 或 /data/local/tmp，并在输出里注明真实路径：

Note: working directory is not writable (failed to open CSV file for writing: ...)
Latencies written to /data/local/tmp/core_latencies_20261117_125613.csv

用 --csv 显式指定的路径不会回退——那种情况代表用户明确的意图，写不进去就直接报错。

6. 参数

参数说明
-i, --iterations N每个线程的成功操作次数，默认 1,000,000
-r, --runs N每个核心对的采样次数，默认 10
-m, --mode MODEbounce（默认，两个线程抢同一条 cache line）或 owned（各写各的 line 再读对方的）
--cpus N最多用 N 个逻辑槽位；不等于绑定到物理核
--perf-onlyApple 专用，Android 上无效果（保留参数是为了命令行一致）
--csv PATH指定输出路径
-y, --yes跳过运行前后的 Enter 等待
--no-progress关闭进度条（管道重定向时自动关闭）
--no-affinity不请求绑核，比较调度器自由摆放时的差异
--list只打印 CPU 信息
-h, --help帮助
--version版本

7. 结果解读

  • 测的是两个线程之间的 cache-line 一致性延迟，不是核间拓扑的精确标定。
  • 矩阵行列号是逻辑槽位；Android 上报的核编号还会被 cgroup 的 cpuset 重新编号。
  • 手机会热降频：同样参数，先跑的几组数值往往比后面低。测对比要固定在电源模式、

关掉后台应用，并在两组之间留出冷却时间。

  • 矩阵里的 N/A 表示该核心对绑核失败、没有可信数字（见 5.3 节），统计时直接剔除。
  • --no-affinity 与默认（请求绑核）的差别，可以粗略反映调度器把线程搬来搬去带来的影响。
  • 不同手机之间的绝对数值不能直接比较，只能在同一台设备、同一状态下横向比参数。

8. 常见问题

No such file or directory（脚本明明在）

说明 ABI 选错了。32 位系统不能跑 arm64 程序，反之亦然。用第 2 节的命令确认 ABI。

注意还有一种情况：文件传过去但没有执行权限，也会报一样的错。

chmod +x CoherencyLatency-arm64-v8a

Permission denied

同上，补 chmod +x，或换到 /data/local/tmp 再试。

测出来比电脑高很多

正常。手机 CPU 的核间一致性延迟、调度开销、降频都比桌面平台高；模拟器上更是几十到一百多 ns。 这个工具的价值是横向比较同一台设备的不同参数/模式，不是和 PC 比绝对值。

能不能跑满 8 核

可以，但很慢也很热。--cpus 不设就是全部逻辑槽位。建议从 2–4 开始。

会不会影响保修 / 需要 root

不需要 root，不写系统分区，不改任何系统设置。程序只在当前目录（或 --csv 指定处）生成一个 CSV。 删除文件即卸载。

9. 校验文件完整性

sha256sum CoherencyLatency-arm64-v8a

与 SHA256SUMS 中的值比较。Termux 里没有 sha256sum 时可用 toybox sha256sum 或 busybox sha256sum。

10. 源码与构建

源码在 Android-移植/ 目录（单一 src/main.cpp + build_cli.py + make-android-zip.py）。 构建用 NDK r21e（D:/ndk21/android-ndk-r21e），四个目标分别是 aarch64-linux-android21、armv7a-linux-androideabi16、i686-linux-android16、x86_64-linux-android21， 编译参数含 -O3 -static-libstdc++ -s，详见 build_cli.py。
