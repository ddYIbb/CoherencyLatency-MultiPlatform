Windows / macOS 图形界面版使用说明

CoherencyLatency 1.2.0 桌面图形界面版。与命令行版共用同一套测量引擎（windows/src/CoherencyLatency.cpp），因此矩阵数值、CSV 格式与命令行版完全一致。

一、Windows 版

运行

Release 里的 CoherencyLatency-Windows-GUI-v1.2.0.zip 解压后只有一个 CoherencyLatency.exe，这是单文件程序，双击即可运行，不需要安装、不写注册表、不需要 Visual C++ 运行库。

它内部同时带有 x86、x64、ARM64 三份原生程序：启动时按当前系统自动挑一个释放到 %TEMP% 再运行，退出后删除临时文件。首次启动时 Windows Defender 可能扫描几秒到几十秒，属正常现象。

最低系统与命令行版一致：x86 / x64 需要 Windows Vista SP2 及以上，ARM64 需要 Windows 10 及以上（与系统位数对应，启动器自动匹配）。

界面

按 Windows 11 Fluent 风格绘制，跟随系统深色/浅色模式、强调色与高对比度：

  • 设备信息：逻辑线程数、缓存行大小、架构；物理核数与同核超线程分组；测量对象说明；固定参数；版本号。
  • 测量范围：自动测量本机全部逻辑线程，没有线程数选项；线程越多对数越多（n×(n-1)），耗时相应增加。
  • 开始测试 (Alt+S)：跑完整的 n×n 矩阵。
  • 停止 (Alt+T 或 Esc)：请求中止，当前线程对跑完后停下，已完成结果保留。
  • 导出 CSV (Alt+E)：另存一次结果。
  • 状态行：就绪 / 测量中 x/y · T2↔T5 113.5 ns · 用时 3.2 s / 完成 · 56 个线程对 · 用时 12.4 s / 已停止 · 完成 6/56 个线程对 · 用时 2.1 s。只在每个线程对完成时刷新一次，不会高频跳动；某一对绑核失败时显示 T2↔T5 N/A，不带单位。
  • 矩阵：热力着色，对角线为 x，未测为 ·，完成填数值（单位 ns/op）。带 * 的线程互为同核超线程，这些格子通常明显更快（约 30 ns）。
  • 矩阵卡：默认竖向 600×880 的紧凑窗口，矩阵占满剩余空间。线程数超过 12 时矩阵只画色块（不写数字，数值看导出的 CSV），格子自动缩小，32×32 也能整幅放下，不需要滚动。
  • 自动保存：每次跑完自动把 CSV 写到 %USERPROFILE%\Documents\CoherencyLatency，文件名 core_latencies_<日期>_<时间>.csv，底栏会显示实际目录。

命令行版在哪

GUI 版和命令行版是两个独立文件，命令行版仍是 CoherencyLatency-Windows-v1.2.0.exe（同一个单文件启动器，控制台程序）。需要脚本化、批量跑或写 CSV 到指定路径时用命令行版，参数见 docs/Windows-使用说明.md。

二、macOS 版

运行

Release 里的 CoherencyLatency-macOS-GUI-v1.2.0.zip 解压后得到 CoherencyLatency.app 和独立的 CoherencyLatency 可执行文件。

  • 双击 CoherencyLatency.app 即可运行。
  • 首次打开若被 Gatekeeper 拦截，右键点图标选「打开」，或执行：
xattr -dr com.apple.quarantine CoherencyLatency.app
  • CoherencyLatency.app 同时包含 Intel（x86_64，最低 macOS 10.10）和 Apple Silicon（arm64，最低 macOS 11.0）两个切片，不需要选版本。

界面

按 macOS 原生 AppKit 风格绘制，自动跟随系统深色/浅色模式、强调色和增强对比度（辅助功能）：

  • 与 Windows 版同样的信息骨架：设备信息、开始/停止/导出、状态行、进度条、热力矩阵、图例与平均/最小/最大值、自动保存路径；同样没有线程数选项，固定测量全部逻辑线程。
  • 状态行同样只在每个线程对完成时刷新一次。
  • 热力色公式两端完全一致，同一个矩阵在 Windows 和 macOS 上颜色相同。

自动保存与调度限制

  • CSV 自动写到 ~/Documents/CoherencyLatency。
  • macOS 不支持硬性 CPU 绑定。程序会请求尽力而为的 QoS 提示，但系统仍可能把线程在性能核与能效核之间迁移，所以矩阵下标是逻辑槽位，不是经过验证的物理核心编号。这一点与 macOS 命令行版一致，命令行版也不会出现 N/A。

四、常见问题

Q：窗口能缩放吗？ 能。默认 600×880（竖向、紧凑），最小 520×760。窗口变小时矩阵会自动缩小单元格；线程数较多（超过 12 个）时只画色块，不写数字，仍能整幅放下。

Q：为什么同核超线程的格子明显更快？ 因为两个线程在同一个物理核的不同超线程上，共享 L1/L2，缓存行不需要跨核传递。

Q：为什么线程数越多，用时增长很快？ 线程对数是 n × (n - 1)，8 线程 56 对，16 线程 240 对，32 线程 992 对。默认每对 1,000,000 次原子操作 × 3 轮。

Q：能不能只测某几个核？ 图形界面版固定测量全部逻辑线程，不提供选择；要精确指定核心请用命令行版的 --cpus 或直接改源码。

Q：结果文件在哪？ Windows 是 %USERPROFILE%\Documents\CoherencyLatency，macOS 是 ~/Documents/CoherencyLatency，底栏会显示完整路径；也可以用「导出 CSV」另存。
