# CoherencyLatency macOS 使用手册

**版本：** 1.0.0（对应 MicroBenchX 1.0.5）  
**适用平台：** Intel（x86_64）Mac：macOS 10.7 Lion 或更高；Apple Silicon（arm64）Mac：macOS 11.0 或更高。主程序为 Universal 2 单文件。

> **重要限制**：macOS 不提供硬性 CPU 绑定。本工具**不能保证**测量“指定 core i ↔ core j”的核间延迟；矩阵中的 `i`/`j` 只是逻辑槽位，不是物理核心编号，也不保证线程落在指定的 P 核或 E 核上。若要测量严格的核心对延迟，请使用原版 Windows 程序，或 Linux 上支持 `taskset`/`sched_setaffinity` 的环境。

## 1. 文件夹内容

```text
CoherencyLatency-macOS-Release/
└── CoherencyLatency      主程序（Universal 2：x86_64 + arm64）
```

主程序是自包含的 Universal 2 可执行文件（Intel x86_64 + Apple Silicon arm64），只依赖 macOS 自带的 `/usr/lib/libSystem.B.dylib`，不需要安装 Homebrew、CMake 或其他运行库。

## 2. 首次运行

### 2.1 放到本地目录

建议先把整个文件夹复制到“应用程序”或“下载”之外的位置，例如：

```text
~/Applications/CoherencyLatency-macOS-Release
```

不要直接在 ZIP 压缩包里运行。

### 2.2 解除权限和隔离

打开“终端”，进入文件夹：

```bash
cd ~/Applications/CoherencyLatency-macOS-Release
chmod +x CoherencyLatency
xattr -dr com.apple.quarantine .
```

如果 macOS 仍提示“无法打开，因为无法验证开发者”：

1. 在 Finder 中右键点击 `CoherencyLatency`，选择“打开”；
2. 或到“系统设置 → 隐私与安全性”中点击“仍要打开”；
3. 仍不行时执行：

```bash
codesign --force --deep --sign - CoherencyLatency
```

### 2.3 先检查程序

```bash
./CoherencyLatency --list
```

应看到 `CoherencyLatency 1.0.0` 和 CPU 信息。`--list` 不会运行测试。

## 3. 启动方式

单文件版直接从「终端」运行即可；下文的命令行示例适用于所有测试方式。

> 标准测试在核心数较多的 Mac 上会运行很久。第一次使用建议先运行下面的“快速测试”。


## 4. 命令行使用

### 4.1 查看 CPU

```bash
./CoherencyLatency --list
```

### 4.2 快速测试

```bash
./CoherencyLatency --yes --cpus 2 --iterations 100000 --runs 3
```

只使用 2 个逻辑槽位，适合先确认程序能运行和观察大致延迟。

### 4.3 标准测试

```bash
./CoherencyLatency --yes
```

默认参数是每个线程 1,000,000 次操作、每个核心对 10 runs。核心数越多，耗时增长很快；可以随时按 `Ctrl+C` 停止。

### 4.4 owned 模式

```bash
./CoherencyLatency --yes --mode owned --cpus 2 --iterations 100000 --runs 3
```

`bounce` 模式让两个线程竞争同一条 cache line；`owned` 模式让两个线程各自写自己的 cache line，再读取对方的 line。

### 4.5 指定 CSV 路径

```bash
./CoherencyLatency --yes --csv result.csv
```

不指定时，默认写入当前目录的：

```text
core_latencies_YYYYMMDD_HHMMSS.csv
```

### 4.6 兼容原版位置参数

```bash
./CoherencyLatency 1000000 bounce
./CoherencyLatency 1000000 owned
```

## 5. 输出格式

### 5.1 终端显示

终端输出是逗号分隔的矩阵，对角线为 `x`：

```text
x,123.456789
123.456789,x
```

### 5.2 CSV 文件

CSV 与原版 v1.0.5 一致：

- 文件名：`core_latencies_YYYYMMDD_HHMMSS.csv`
- 分隔符：分号 `;`
- 第一行：`;Core 0;Core 1...`
- 每一行：`Core i;值;值...`
- 对角线：`x`
- 数值按原版 `defaultfloat` 精度 6 输出

原版输出的是 **CSV，不是 XLSX**。CSV 可以直接用 Excel 或 Numbers 打开，也可以在 Excel 中另存为 `.xlsx`；程序本身不生成 xlsx。

## 6. 参数表

| 参数 | 说明 |
| --- | --- |
| `-i, --iterations N` | 每个线程的成功操作次数，默认 1,000,000 |
| `-r, --runs N` | 每个核心对的采样次数，默认 10 |
| `-m, --mode MODE` | 测试模式：`bounce`（默认）或 `owned` |
| `--cpus N` | 最多使用 N 个逻辑槽位；不保证绑定到对应物理核心 |
| `--perf-only` | 按 `perflevel0` 数量限制逻辑槽位；不保证线程实际落在 P 核 |
| `--csv PATH` | 指定 CSV 输出路径 |
| `-y, --yes` | 跳过测试前后的 Enter 提示 |
| `--no-progress` | 禁用进度条 |
| `--no-affinity` | 关闭 best-effort affinity/QoS 设置 |
| `--list` | 打印 CPU 信息后退出 |
| `-h, --help` | 显示帮助 |
| `--version` | 显示版本 |

## 7. 结果解读与限制

- 本移植测量的是两个线程之间的 **cache-line 一致性延迟样本**，不是严格的核心对拓扑矩阵。
- 矩阵的行列号只是逻辑槽位，不能解释为“物理 Core 0 到 Core 1”的延迟。
- macOS 调度器可能迁移线程，尤其是 P 核与 E 核之间；同一台 Mac 上不同次运行也可能有差异。
- 不要直接把 macOS 的数值和 Windows 原版数值比较；平台和调度模型不同。
- 想获得相对稳定的对比：连接电源、关闭其他应用、避免热降频，并固定 `--cpus` 和 `--perf-only` 的组合。

## 8. 性能与内存

本移植在保持命令行参数、测试次数、统计方式和输出格式完全不变的前提下，降低了运行开销和内存占用：

- **矩阵内存由 O(n² × runs) 降到 O(n²)**：原版会把每个核心对、每次 run 的原始样本全部存进内存，最后再求最小值；现在每得到一个样本就与当前最小值比较并保留较小者，只保留最终的 `n × n` 最小延迟矩阵。以 32 个逻辑槽位、10 次 run 为例，样本内存从约 40 KB 降为固定的 4 KB（`32 × 32 × 4` 字节），并且不再随 `--runs` 增长；槽位越多、run 越多，节省越明显。
- **没有堆分配**：采样用的 cache-line 单元改为栈上对象，`bounce` 和 `owned` 两种模式都不再使用 `new`/`make_unique`，整个程序没有显式的动态内存分配。
- **参数只读传递**：矩阵计算以 `const Options&` 接收配置，避免重复拷贝。
- **输出完全不变**：CSV 的列顺序、对角线 `x`、6 位有效数字精度与原版一致；调大 `--runs` 只会让采样更久，内存占用不再增加。

> 说明：减小 `--iterations` 或 `--runs` 会直接缩短运行时间，那属于测量本身的耗时，不是额外开销。程序常驻内存只有几 MB，长时间测试也不会持续增长。

## 9. 常见问题

### 提示“Permission denied”

```bash
chmod +x CoherencyLatency
```

### 提示“cannot be opened because the developer cannot be verified”

按 2.2 节执行 `xattr`，或在 Finder 中右键选择“打开”。

### 提示“bad CPU type in executable”

说明当前系统版本低于本程序的最低要求（Intel Mac 需 macOS 10.7+，Apple Silicon Mac 需 macOS 11.0+），或者文件下载不完整/架构识别异常。本程序是 Universal 2 单文件，同时包含 x86_64 和 arm64。

### 程序被系统杀掉

尝试重新签名：

```bash
codesign --force --deep --sign - CoherencyLatency
```

### 测试运行太久

按 `Ctrl+C` 停止，改用：

```bash
./CoherencyLatency --yes --cpus 2 --iterations 100000 --runs 3
```

### 想确认文件没有损坏

```bash
shasum -a 256 CoherencyLatency
```

把输出与 `SHA256SUMS` 中的值比较。

## 10. 卸载

直接删除整个文件夹即可。程序不会写入系统目录，也不会安装后台服务；CSV 文件默认写在当前运行目录。
